1How to read this

Every model below is served by the local Our Free Model gateway with no login and no API key. The rank is the picker order: a practical blend of capability ceiling, context/output size and measured latency — it is guidance for picking a model fast, not a benchmark result. Free lanes rotate: when one model returns 429/503, the combo or a router covers the same request.

Lane meaning. free = OpenCode Zen free lane (frontier models, large injected system prompt ≈ 5.6–6.4k tokens per request). kilo = Kilo AI's keyless isFree pool (≈2k tokens overhead; prompts may be logged upstream). combo = a local failover chain, not a model. Vision = accepts images. Out = max output tokens — the column that quietly matters most for big rewrites and document generation.

Reading the numbers. Free-lane models are fastest but carry a large injected system prompt (that's the cost of keyless frontier access); Kilo lanes are leaner; FCC via OpenRouter is the leanest and slowest. A one-line question costs ~5.9k tokens on the free lane — for cost-sensitive bulk work prefer the utility-tier kilo models or the fcc provider.

Ranking caveat. These are latency and size facts plus practical fit. No benchmark scores are implied; upstream rosters change and quotas rotate. Re-run npm run bakeoff any time for a fresh scorecard.

6Using them in OpenCode

  • Select: /models → provider 00-free → NN-name. The numbers are the ranking.
  • Refresh the roster after upstream changes: npm run sync (re-pulls live models, keeps this order).
  • Reorder the top: edit the PRIORITY array in bin/sync-models.mjs, then npm run sync. Unlisted new models append alphabetically — nothing disappears.
  • Privacy: Kilo-lane prompts may be logged upstream; route anything sensitive through your own aggregate keys (dashboard → Aggregate) or local Ollama via the fcc provider.
  • More lanes (dashboard at http://127.0.0.1:18900): EAC (GitHub sign-in + star) and account channels (LobsterAI, Qoder, TRAE, Cline, Loomy, Raccoon, MiniMax Code, ZCode, Gemini) add models after you sign in.

7Where this came from — and how it actually works

No model is hosted by this stack. Every answer comes from a real upstream you can audit. The two things that are local are a loopback gateway and the small repo that wires it into OpenCode.

LaneUpstreamHow it's reachedGood to know
freeOpenCode Zen inference
opencode.ai/inference/v1/*		Authorization: Bearer public, a minted per-request session id, and the official v2 client fingerprintDirect upstream access — not a bridge through OpenCode. The fingerprint is why a one-line prompt costs ~5.9k tokens.
kiloKilo AI public gateway

comboThis machineNamed failover chains defined in the gatewayNo upstream of its own — it just tries the next free link when one dies before answering.
fccOpenRouter + your local Ollamafree-claude-code on 127.0.0.1:8082 (Anthropic Messages)Leanest prompts (~22 tok). Optional second gateway, not required for anything above.
The local pieces. Our Free Model (Ebony-Vinyl/dsh-our-free-model, MIT) runs as a loopback service on 127.0.0.1:18900 and speaks OpenAI Chat, OpenAI Responses and Anthropic Messages. free-claude-code (Alishahryar1, AGPL-3.0) runs on 127.0.0.1:8082, installed at runtime via uv — never bundled here. free-model-bridge (KoBadger, MIT) ships no gateway code at all: just setup, sync, verify, bake-off and this guide. Upstream is cloned straight from GitHub, so what runs on your machine is auditable. No affiliation with OpenCode, DeepSeek, Ebony-Vinyl or Alishahryar1. The bare dsh-our-free-model package on npm is a third-party repackage — this repo clones the source instead.
Security posture. Loopback only, LAN relay disabled, gateway API key kept in ~/.our-free-model/settings.json as forwardKey, and HOST=127.0.0.1 pinned in ~/.fcc/.env (the FCC default is 0.0.0.0 — LAN-exposed with no auth). Nothing needs admin rights; autostart uses your Startup folder, not Task Scheduler.

8Get it running from the repo

Prereqs: Node ≥ 22.19 (or ≥ 24) and git. Optional: Bun for a faster free-lane transport, and uv (it fetches Python 3.14 itself) only if you want FCC.

git clone https://github.com/KoBadger/free-model-bridge
cd free-model-bridge
npm run setup            # add -- --with-fcc for the second gateway
StepWhat npm run setup does
1 · fetchShallow-clones the OFM gateway into ~/Apps/our-free-model (or ~/our-free-model on macOS/Linux).
2 · startStarts the gateway on 127.0.0.1:18900 if it isn't up, and waits for /health.
3 · configCreates ~/.config/opencode/opencode.json if missing; a timestamped backup is written before every change.
4 · providerWrites the 00-free provider with the live roster and the provider.use allow entry. The digits-first id is why this group sits on top.
5 · autostartCreates a Startup-folder shortcut (no admin). macOS/Linux prints a systemd user-unit line instead.
6 · optional FCCInstalls free-claude-code via uv on Python 3.14.10, pins HOST=127.0.0.1, starts it, wires the fcc provider and its shortcut.

Everyday flow.

  • /models → 00-free → NN-name.
  • npm run sync — re-pull the live roster into OpenCode.
  • npm run guide — regenerate this PDF and the field notes from that roster.
  • npm run bakeoff — fresh latency + correctness scorecard.
  • npm run verify — the full health check.

OpenCode hot-reloads config, so nothing needs a restart.
